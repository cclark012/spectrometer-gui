## Outcome

The timing files identify the main iDus throughput problem. Re-arming SDK2 for
each frame takes roughly 117 to 200 ms at the tested settings, while one armed
Run-Till-Abort stream delivers frames at the requested 15 or 50 ms period. The
transfer itself is normally about 0.04 to 0.10 ms. The GUI now uses a persistent
SDK2 circular-buffer stream for Live, automated rapid, and gated acquisitions,
with one explicit preparation frame before a gated sequence begins. A Python,
PySide6, or whole-application C++ rewrite is not supported by this evidence.

The revision also completes the answered magnetic-field applicability behavior,
online gated timing policy, requested/applied exposure truth, guided iDus warm-up,
conditional schema-v4 metadata, selected Newport channel association, compact
acquisition controls, smoothing windows/previews, and asynchronous spectrum
autosave.

The 09/11 lab log identified one Run-Till-Abort synchronization defect. After
the adapter discarded frames completed between GUI requests,
`WaitForAcquisitionTimeOut` could acknowledge the discarded frame's stale SDK
event and return success while the circular buffer was empty. The subsequent
`GetOldestImage` then returned `DRV_NO_NEW_DATA`. Readiness now requires a
non-empty `GetNumberNewImages` range; stale successful wakes are ignored within
the original bounded timeout. No non-Andor acquisition behavior was changed.

The lab retest then completed the gap probe 100/100 times and confirmed GUI Live
and multi-frame gated operation. Its indices advanced monotonically from 1 to
694 while 594 old frames were drained and 99 stale notifications were recovered.
That closes the original repeated-acquisition failure.

The gated CSVs revealed a different problem: at 0, 150, 300, 450, and 600 ms
targets, the selected exposure midpoint was consistently about 9.4 to 11.5 ms
early. This is not a timer-reset or save-order artifact. A continuously exposed
frame can complete readout after the request even when its exposure occurred
before the target. The adapter now discards those candidates and returns the
first frame whose estimated exposure midpoint is at or after the absolute gated
target.

The non-TEC details controls now use a visible, pinned **Apply and verify** action.
The worker serializes settings changes, stops any active stream, waits for Kymera
motor readback, refreshes calibration/capabilities, and returns explicit success
or failure to the still-open dialog. A read-only-by-default controls probe uses
the same production adapter path and restores test changes unless told not to.

The enumerated vertical shifts are 8.25, 16.25, 32.25, and 64.25 microseconds per

selectable.

The stream's first frame still pays about 0.88 to 0.90 seconds of one-time
`PrepareAcquisition` cost plus 16 to 32 ms to start. The GUI therefore arms and
consumes an unsaved frame before a time-sensitive gated sequence. It keeps the
stream armed while settings and the workflow owner remain unchanged.

The evidence does not include a 1, 5, or 10 ms Run-Till-Abort request. The GUI now
allows any positive whole-millisecond request, reads `GetAcquisitionTimings` after
SDK2 applies it, and records the applied value as primary metadata. If a 5 ms
request is clamped to 13.24 ms, the file records 13.24 ms plus the differing 5 ms
request. If mode 5 reports 5 ms applied with a longer frame period, the file
correctly preserves 5 ms exposure and the separate throughput limit.

bench measurements.

## 2026-09-14 lab evidence and implementation

The reversible control matrix establishes a clear production boundary. Grating,
center wavelength, Kymera filter, output flipper, horizontal/vertical shift speed,
and an available preamplifier-gain change all applied and restored. An unavailable
gain index was rejected before a native call. Full-vertical-binning value 4
returned SDK2 `DRV_NOT_SUPPORTED`, and a focus request from readback 423 to 400
returned `ATSPECTROGRAPH_P2INVALID`. The production dialog now exposes only
verified FVB binning 1 and keeps focus readback visible but read-only; the probe
retains both calls for future diagnosis.

The paired stream-gap files confirm the midpoint selector. Both completed 100/100
requests with monotonically increasing indices. Without midpoint alignment, all
99 steady-state exposures began and reached their midpoint before the request
target. With alignment, all were midpoint-eligible; the adapter discarded 198
early candidates, or two per steady-state request. Median worker-call time rose
from 4.367 to 34.353 ms because it deliberately waited for an eligible exposure.
That is the intended timing cost, not a re-arm regression.

The eight GUI CSVs contain no evidence of a reset/save timing defect. Negative
means or minima occur only for the estimated exposure start at a nominal 0 ms
delay. A finite exposure centered after the software OFF reference can begin
before that reference. Request, controller-call, accepted exposure-midpoint, and
timing-error means remain nonnegative in those files.

For weak phosphorescence measurements, this revision adds bounded
**Retain N inside fixed window** acquisition. In averaged delayed-after-OFF and
interleaved-decay modes, Repeats becomes the accepted count required per trace.
The coordinator tests either exposure start or midpoint against a fixed symmetric
window, releases rejected arrays, and repeats complete pump/OFF attempts until
every trace reaches its target or a configurable finite attempt multiplier is
exhausted. Per-frame Newport reads and individual-file output are disabled to
protect timing and avoid hundreds of rejected files. Partial accepted averages
survive a ceiling failure with explicit reason and attempt counts.

The output timing model is now explicit. “Request” is the coordinator emission
time; “acquisition call” bounds the worker's adapter call; “exposure” is the
backend-derived detector-window estimate; and timing error is the signed selected
exposure reference minus requested delay. The laser origin remains software-only:
the OBIS command is acknowledged/read back before the coordinator records its
transition timestamp. There is no laser-box optical or hardware-clock timestamp,
so an external photodiode/DAQ remains required for a physical timing guarantee.

## Metadata and data integrity

Individual spectra use schema v4; one-file gated averages now use schema v5. The
primary intensity column is always the raw adapter result; a processed column appears
only when background subtraction or smoothing changed it. Feature-group presence
indicates applicability, so redundant `*_active` flags remain removed. Normal
Newport status words remain omitted, while abnormal words/command status remain.

Gated-series v5 conditionally adds the fixed-retention settings and attempt
accounting plus an explicit timing-model group. The existing spectrum v4 format
remains at version 4 because the added transition-basis field is backward-compatible
within its key/value metadata model and does not change its data columns.

Approved Andor metadata includes grating, center wavelength, filter, focus,
grating/detector offsets, amplifier, horizontal/vertical speeds, gain, binning,
and optional flipper positions. A/D channel is deliberately omitted. Detector
temperature is still excluded from high-rate per-frame metadata because its
benefit does not justify an unmeasured native-query cost; the cooler workflow
queries it only when requested, connected, or warming.

The strict background SHA-256 signature identifies the backend, serial,
wavelength grid, applied exposure, averaging/corrections, and readback state. It
prevents a mismatched background and avoids duplicating all background settings.
The complete field catalog, replacement map, combinations not made, and proposed
but unapproved fields are in `docs/SPECTRUM_METADATA_SCHEMA_20260909.docx`.

## Architecture differences

- `AndorSDK2Camera` now owns stream arm/read/drain/abort state. The composite
  Andor adapter stays responsible for calibrated spectra and user-facing state.
- `AcquisitionTiming` now describes single versus Run-Till-Abort acquisition and
  carries driver index, discarded backlog, target-alignment discards, pending
  depth, and per-average windows.
- Gated coordination supplies the absolute exposure-midpoint target; the SDK2
  adapter alone owns buffer inspection and candidate selection. The GUI never
  reaches into a vendor buffer.
- Spectrometer Details sends one configuration request through MainWindow and
  InstrumentRuntime to the device worker. Completion returns through a dedicated
  apply/fail signal, so widgets update only after available readback and
  calibration refresh.
- `InstrumentRuntime` still coordinates optional Newport-before/spectrum/Newport-
  after transactions without merging device adapters or worker queues.
- `FileIOController` owns an ordered one-worker autosave executor; manual file
  dialogs remain on the GUI thread.
- The gated planner remains pure and lazy. The coordinator owns deadlines,
  quality classification, averaging, partial-output policy, and laser cleanup.
- Fixed-window retention extends the existing lazy plan by a finite attempt
  ceiling. `RetainedTraceGoal` counts accepted frames by trace identity while the
  accumulator retains only accepted arrays/statistics; it does not create a
  second acquisition engine.
- Andor GUI capabilities are narrowed by confirmed lab behavior: unsupported FVB
  binning and unverified focus motion are not presented as writable even though
  their diagnostic native calls remain available.
- Spectrum serialization remains an explicit versioned boundary. In-memory
  records remain rich while spectrum v4 and averaged-series v5 write conditional,
  analysis-oriented rows.
- The future plugin/procedure layer remains above adapters and below UI-specific
  widgets; no arbitrary extension execution was added.

diagrams plus the major-method index.
